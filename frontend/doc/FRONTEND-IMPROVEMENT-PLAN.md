# DevBit 前端体验改进总计划

更新日期：2026-10-17（北京时间）

状态：前端实现完成，已通过本地逻辑、类型与构建检查；新增接口等待后端适配。交付与验证记录见 [IMPLEMENTATION-REPORT.md](IMPLEMENTATION-REPORT.md)，契约见 [SOCIAL-API-V2.md](SOCIAL-API-V2.md)。

## 1. 目标与最终范围

将 DevBit 定位为「学习与创作社区」，服务于技术与数学交流、作品分享和浏览器图形实验。

保留暖白背景、蓝色强调、胶囊导航、细线图标与首页特色卡片，完善首次访问、阅读、账号、好友与私信体验。

采用接口先行的开发方式：前端按照目标功能完成页面和状态，定义 TypeScript 类型、接口契约、适配层与本地 Mock，等待后端逐项适配。

本计划覆盖：

- 全局配色、字号、圆角、焦点与响应式规范。
- 首页定位、真实近期讨论和功能入口。
- 登录注册中文化、错误反馈、密码显示与账号恢复界面。
- 论坛摘要、日期、搜索与分类的可读性。
- 好友列表、找人、申请、接受、拒绝、撤回、移除及私信衔接。
- 屏蔽、私信偏好、在线状态的前端设计和接口预留。
- 图形实验封面、加载反馈、参数遮挡与画布生命周期。
- 本地验证、截图对照及后端适配清单。

本次不修改 Rust 后端、数据库或线上数据，也不执行线上部署。后端未适配的功能在本地 Mock 中验证，在正式环境通过能力开关明确控制。

本计划统一取代此前「只能使用已有接口，因此暂不设计新增功能」的限制；已有接口和行为仍作为兼容模式保留。

## 2. 当前实现与主要问题

依据此前线上预览，以及本次本地代码核对：

| 模块 | 当前情况 | 改进重点 |
|---|---|---|
| 首页 | 大标题和品牌氛围清楚，实际用途表达较泛 | 明确定位，让访客直接开始使用 |
| 视觉 | 主按钮沿用浅品牌蓝，部分辅助字偏小偏淡 | 独立操作色、加强文字辨识度 |
| 账号 | 页面和校验多为英文；登录错误统一包装为 401 | 中文化、保留真实错误类别、补恢复接口契约 |
| 论坛 | 已有搜索、排序、分类与空状态 | 摘要清理、日期统一、手机输入区优化 |
| 好友 | 直接添加单向联系人，无申请确认 | 完善完整关系状态与双向好友前端流程 |
| 好友加载 | 请求失败可能表现为空列表 | 独立加载、空数据、失败与重试状态 |
| 找人 | 未搜索即可能显示无结果；响应顺序无保护 | 明确状态、最新请求优先、防重复操作 |
| 私信 | 已有会话、发送、未读及 WebSocket | 好友衔接、草稿隔离、可见时已读 |

以上为实施前的审查基线。本轮已使用明确标识的本地 Mock 验证社交界面；真实账号之间的持久化与权限仍待后端联调。此前本地接口错误不作为线上故障结论。

## 3. 全局视觉与交互规范

### 3.1 颜色与字号

| 用途 | 目标规格 |
|---|---|
| 页面背景 | 保留 `#f7f5f2` |
| 卡片背景 | 保留白色 |
| 品牌标题、装饰 | 保留现有浅蓝色与渐变 |
| 主按钮 | `#416bc9 → #3156ad` 渐变，文字 `#ffffff` |
| 主按钮悬停 | `#3156ad` |
| 文字链接、选中项文字 | `#315fb9` |
| 正文 | `#1e1e2e`，通常 16px |
| 次要正文 | 保留 `#4a4a5e` |
| 辅助文字 | `#6c6c7c` |
| 摘要 | 至少 14px |
| 日期、作者、统计 | 至少 13px |

新增操作色变量，不通过整体加深品牌色影响标题、图标和背景。检查存在独立样式的导航 CTA、提交按钮和实验重试按钮，避免只修正通用按钮而遗漏其他入口。

普通尺寸文字对比度以至少 4.5:1 为验收目标；默认、悬停、选中和焦点状态均需抽查。依据：[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

### 3.2 组件与响应式

- 普通按钮、输入框圆角 12px；普通内容卡片 16px；首页特色卡片与胶囊导航保留现有造型。
- 操作目标至少 44×44px，表单输入框高度约 48px。
- 焦点轮廓可见，选中与错误状态同时提供文字或形状线索。
- 保留现有动画机制并支持 `prefers-reduced-motion`。
- 检查 1440×900、1024×768、390×844、320×720；内容自然换行，不用固定高度裁切新增文案。

## 4. 页面与功能设计

### 4.1 首页

页面顺序：导航 → 首屏介绍 → 近期讨论 → 现有四个功能入口 → 页脚。

| 元素 | 内容或行为 |
|---|---|
| 标签 | Beta · 学习与创作社区 |
| 标题 | 从一个问题开始，和 DevBit 一起创造。 |
| 说明 | 交流技术与数学问题，分享作品，体验浏览器里的图形实验。 |
| 主按钮 | 进入论坛 → `/forum` |
| 次按钮 | 探索实验 → `/games` |
| GitHub | 保留团队介绍页已有入口 |

桌面保持居中，首屏最小高度采用 `clamp(480px, 70svh, 640px)`，标题最大 88px；手机保持左对齐，标题 32–40px；360px 以下降至 28px，避免单字换行；高度随内容增长。

近期讨论复用现有公开帖子接口，按发布时间降序、同时间按 ID 降序取前三篇。客户端独立异步加载，不阻挡首屏；采用独立组件承载数据状态。桌面三列、平板两列、手机一列。

卡片显示分类、标题、摘要、作者和中文日期；标题与摘要各最多两行。标题链接到帖子详情，并提供「查看全部讨论」入口。

| 状态 | 表现 |
|---|---|
| 加载中 | 三张固定尺寸骨架卡片，避免布局跳动 |
| 成功 | 展示实际数量，最多三篇 |
| 空数据 | 「讨论从第一个问题开始」及论坛入口 |
| 失败 | 「讨论暂时无法加载」及重试按钮 |

四张功能卡片保留不等宽布局；「游戏」改为「实验」。排行榜在卡片和导航中标注「筹备中」，继续使用原路由。

### 4.2 账号流程

- 导航、登录注册、页面标题、字段、按钮、校验与前端错误提示统一中文。
- 登录标题为「欢迎回来」，说明为「登录 DevBit，继续讨论与创作。」。
- 注册标题为「加入 DevBit」，Name 改为「昵称」，说明「大家将通过这个名字认识你」。
- 注册密码规则固定显示在输入框下方：「至少 8 位，包含字母和数字」。保留现有规则与自动填充。
- 增加显示／隐藏密码按钮，切换时保留输入，按钮不提交表单。
- 验证码保留现有发送与倒计时；文案改为「发送验证码」「正在发送…」「60 秒后重新发送」。
- 提交时校验，失败后聚焦首个错误字段；修改已报错字段时重新校验。
- 字段使用 `aria-invalid`、`aria-describedby`；全局错误可以被辅助技术感知。
- 请求中禁止重复提交，失败保留输入。注册成功沿用跳转登录页，增加成功提示。

先修正错误归一化：保留真实 HTTP 状态，避免将网络或服务器错误统一包装为 401。按稳定错误码映射中文文案，未知错误使用对应操作的通用提示。

账号恢复设计为：填写邮箱 → 获取验证码 → 填写验证码与新密码 → 成功后重新登录。接口尚未适配时，入口明确显示暂未开放；本地 Mock 可验证完整流程。

### 4.3 论坛与阅读

- 日期统一为「刚刚」「X 分钟前」「X 小时前」「X 天前」；30 天及以上显示北京时间 `YYYY-MM-DD`。
- 无效日期保持为空，未来时间按「刚刚」处理；首屏服务端与客户端输出保持一致。
- 摘要改为基于 Markdown 解析结果生成纯文本，默认最多 120 字符。
- 保留标题、列表、链接和行内代码文字；图片保留替代说明；跳过代码块与原始 HTML；公式使用「〔公式〕」。
- 合并多余空白，空摘要显示「查看完整内容」；正文继续使用现有 Markdown 与公式渲染。
- 手机标题最多两行；搜索提示缩短为「搜索帖子」，排序按钮保留图标和当前值。
- 分类栏增加可横向滑动的渐隐提示，到末端后消失。
- 搜索无结果与空分类使用不同提示，并提供清除筛选入口。
- 测试帖清理属于内容管理，不由本轮前端自动删除或隐藏。

### 4.4 好友与找人

新模式的主标签为「私信」「好友」「找人」，好友页增加「好友申请」子入口并显示收到的待处理数量。

好友页顶部显示好友数量、本地搜索、添加好友和刷新入口。列表行显示头像、昵称、未读消息与「发消息」，管理操作置于更多菜单。空列表提供「寻找社区成员」。

找人采用 300ms 防抖，回车立即搜索，中文输入法组词期间不请求。清空输入恢复初始提示；只接受最新关键词与当前账号的响应，旧请求不得覆盖新结果。

| 搜索状态 | 表现 |
|---|---|
| 未输入／未搜索 | 提示输入昵称 |
| 加载中 | 正在查找… |
| 有结果 | 显示用户与对应关系操作 |
| 无结果 | 建议调整昵称关键词 |
| 失败 | 显示失败原因与重试，不显示成无结果 |

关系与操作分别管理：

| 关系 | 操作 |
|---|---|
| 自己 | 显示「你自己」 |
| 无关系 | 添加好友 |
| 已发出申请 | 等待验证、撤回申请 |
| 收到申请 | 接受、拒绝 |
| 已是好友 | 发消息、管理好友 |
| 已屏蔽 | 取消屏蔽 |

每个用户独立记录处理中状态，同一操作禁止重复提交。只有服务端确认成功才更新关系；失败保留原关系，在对应行提供重试。

发送申请后显示「申请已发送，等待对方确认」。接受后双方成为好友；拒绝、撤回后刷新关系，不残留待处理计数。关系已被其他设备改变时重新获取状态。

移除好友使用明确的确认弹层，显示目标昵称；取消不请求，失败保留原项，成功后移除。新模式的移除为双向解除关系，已有聊天记录保留。

屏蔽列表与私信偏好提供独立设置入口。屏蔽阻止新申请和私信，不自动清除聊天记录；取消屏蔽后从服务端重新获取关系。权限与关系变化最终以服务端返回为准。

### 4.5 私信衔接与移动端

- 从好友或搜索结果进入会话，显示明确的对象身份，并能返回来源列表。
- 草稿按「账号＋聊天对象」隔离，切换对象不会带错草稿；发送失败保留内容。
- 移除好友后保留已有会话的身份与记录，发送权限根据服务端关系及偏好更新。
- 会话打开、窗口未最小化且页面可见时才标记已读；进入好友列表或后台不清除未读。
- 账号切换或退出时清理好友、申请、搜索结果、草稿与操作状态，忽略旧会话的迟到响应。
- 在线状态先获取快照，再消费增量事件；断线与未确认时显示未知，不能当作所有人离线。
- 「清除聊天记录」若只更新本地内存，不能表现为服务端永久删除；持久化清除通过独立接口适配，语义仅影响当前用户的历史可见性。

手机使用接近全屏的面板，隐藏拖拽、缩放与停靠控件；列表和会话分层，通过返回按钮切换。标题与搜索栏固定，内容独立滚动，输入区适应软键盘和底部安全区域。

键盘可操作标签、列表与菜单；关闭弹层后恢复焦点。桌面继续保留现有浮动窗口能力。

### 4.6 图形实验

- 文案统一为「实验」，保留 `/games` 及现有详情路由。
- 卡片说明使用「交互图形实验 · 推荐桌面键盘」，主动作「开始实验」，次动作「查看操作」。
- 使用真实实验截图作为封面，捕获发光图形区域，避开网页按钮与参数文字。
- 返回按钮移至左下角，至少保留 16px 边距并考虑安全区域；帮助保留右上角，左上角参数完整可见。
- 加载提示区分「正在加载实验程序」与「正在准备图形环境」。
- 等待超过 15 秒时提示可继续等待或返回，不显示虚构百分比，也不因此直接判定失败。
- 初始化完成并发现、配置画布后才进入运行状态；初始化结束后 5 秒仍无画布，显示失败及重试。
- 保留画布复用；清理计时器与监听；加载中退出、再次进入、缩放及上下文丢失均需验证。
- 本轮不增加手机触屏参数控制，手机入口说明桌面键盘建议。

## 5. 接口先行的实现结构

结构统一为：页面组件 → 业务状态 → API 适配层 → 真实接口或本地 Mock。

- 页面不直接拼接 URL，不依据后端英文字符串决定业务行为。
- 业务层处理关系状态、列表刷新、按用户的操作锁及账号隔离。
- 适配层复用现有 `useApiFetch`，集中处理路径、响应归一化和错误码。
- 继续使用同源 Cookie 认证方式；保留现有接口及类型的兼容入口。
- 新类型独立维护，覆盖分页、关系、申请、在线快照、偏好与错误；不把旧 `FriendInfo` 直接解释为双向好友。

### 5.1 数据模式与能力开关

| 模式 | 行为 |
|---|---|
| `legacy` | 默认；使用现有真实接口，单向关系以联系人语义呈现 |
| `v2` | 使用新契约，启用后端已适配的申请、双向关系等能力 |
| `mock` | 仅本地开发与测试，使用与新契约相同的结构验证完整流程 |

拟新增 `NUXT_PUBLIC_SOCIAL_MODE`，默认 `legacy`；账号恢复通过独立能力开关控制，默认关闭。V2 内的屏蔽、偏好、在线快照及历史清除也按实际适配能力逐项启用。

Mock 接管演示流程中的好友、申请、会话、发送与已读，避免与真实社交写请求混用。开发预览明确标识 Mock；生产构建不得启用该模式。

正式环境未开放的功能显示明确的暂未开放状态。真实接口失败展示错误与重试，不能自动回退到 Mock 或旧写接口并显示成功。

### 5.2 通用契约

- 接口路径以下表为待适配草案，不表示当前线上已存在。
- HTTP 字段使用 `camelCase`，用户 ID 沿用数字；时间使用 ISO 8601，前端按北京时间显示。
- 分页列表返回 `{ items, nextCursor }`；`nextCursor` 为字符串或 `null`。
- 错误返回 `{ error: { code, message, fieldErrors?, retryAfterSeconds? } }`，同时保留真实 HTTP 状态。
- 关系与权限由后端返回；前端根据结果更新界面，不自行推断已成为好友。
- 重复操作与跨设备变化应可恢复：重复发送同一待处理申请返回现有申请；申请已处理或关系变化时返回稳定错误码，并由前端刷新。
- 当前公开用户信息不足以支持的资料字段先不展示，不构造虚假个人资料或在线状态。

核心类型：`Page<T>`、`SocialUser`、`Friendship`、`FriendRequest`、`RelationshipState`、`PresenceSnapshot`、`SocialPreferences`、`ApiError`。申请状态包含 `pending / accepted / rejected / cancelled`；关系状态与请求处理中状态分开。

### 5.3 待适配的社交接口

基础前缀：`/api/v2/social`。

| 功能 | 方法与路径 | 关键约定 |
|---|---|---|
| 搜索用户 | `GET /users?q=…&cursor=…` | 返回公开用户、与当前用户的关系、可执行动作 |
| 好友列表 | `GET /friends?cursor=…` | 返回双方已确认的关系，不混入单向联系人 |
| 申请列表 | `GET /friend-requests?direction=incoming\|outgoing&status=pending&cursor=…` | 包含申请 ID、双方、状态、留言、时间 |
| 发出申请 | `POST /friend-requests` | 请求 `{ recipientId, message? }`，返回申请 |
| 接受申请 | `POST /friend-requests/{id}/accept` | 双向建立关系，刷新申请与好友列表 |
| 拒绝申请 | `POST /friend-requests/{id}/reject` | 更新申请，刷新双方视角的关系 |
| 撤回申请 | `DELETE /friend-requests/{id}` | 仅发送方撤回待处理申请 |
| 解除好友 | `DELETE /friends/{userId}` | 双向解除，保留会话历史 |
| 在线快照 | `GET /presence?userIds=…` | 返回有权限查看的状态与快照时间 |
| 屏蔽列表 | `GET /blocks?cursor=…` | 返回当前用户的屏蔽记录 |
| 屏蔽用户 | `PUT /blocks/{userId}` | 同步限制申请与私信，保留聊天历史 |
| 取消屏蔽 | `DELETE /blocks/{userId}` | 重新获取关系和可执行动作 |
| 读取偏好 | `GET /preferences` | 返回当前私信、好友申请接收偏好 |
| 更新偏好 | `PATCH /preferences` | 部分更新，返回生效后的完整偏好 |
| 清除自己的会话历史 | `DELETE /conversations/{userId}/history` | 仅改变当前用户历史可见性，不删除对方记录 |

偏好预留 `messagePolicy: everyone / friends / nobody`、`friendRequestPolicy: everyone / nobody`。服务端返回实际配置；前端首次加载不主动覆盖默认值。

现有消息列表、发送、已读端点继续由适配层复用。后端接入关系与偏好规则时，需要同步在实际发送端点校验权限，不能只调整按钮可用性。

### 5.4 账号恢复接口预留

基础前缀：`/api/v2/account`。

| 功能 | 方法与路径 | 关键约定 |
|---|---|---|
| 发送恢复验证码 | `POST /password-reset/code` | `{ email }`，返回通用受理提示、有效期与重发等待时间 |
| 重置密码 | `POST /password-reset/confirm` | `{ email, code, password }`，成功后引导重新登录 |

确认密码仅用于前端校验。有效期与重发等待时间使用接口返回值；过期、错误和限流均有稳定错误码及恢复入口。

### 5.5 实时事件预留

预留 `friend_request_received`、`friend_request_updated`、`friendship_changed`、`presence_snapshot` 与 `presence_changed`。

事件包含对应申请或用户标识，用于使相关缓存失效并重新获取数据；事件本身不直接构造最终好友列表。重连后刷新好友、申请、会话未读及在线快照，避免丢失增量事件造成不一致。

新事件通过适配层归一化，保留现有 WebSocket 消息类型的兼容处理。
