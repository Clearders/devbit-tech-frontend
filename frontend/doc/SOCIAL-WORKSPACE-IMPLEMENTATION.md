# 好友中心与私信工作台交付记录

日期：2026-10-18。范围：前端、开发 Mock、后端接口契约；未修改后端、数据库或部署线上环境。

## 已实现

- 独立 `/friends`：分类、服务端搜索、在线/星标、收发申请、申请留言、私人备注、单一分组及 CRUD、公开资料与近期帖子、隐私和屏蔽。
- 独立 `/messages` 与 `/messages/:userId`：会话搜索、未读、置顶/免打扰/归档、历史分页、日期分隔、连续消息分组、失败重试、会话草稿、表情、图片/文件与图片预览。
- 从旧浮窗、开发预览、帖子作者和评论作者统一进入新页面；导航增加好友入口，其他页面保留社交快捷入口。
- 按 Nuxt 应用/账号隔离共享状态。请求序号处理乱序，账号代次丢弃迟到响应；私信草稿与附件仅存内存。读取回执按可见消息位置推进，避免误读随后到达的新消息。
- 默认 legacy 联系人兼容，扩展按能力开启，真实接口错误不回退 Mock。新增类型、端点、分页、事件和开启条件见 [SOCIAL-API-V2.md](SOCIAL-API-V2.md)。

## 联调边界

以上交互验证使用明确标识的开发数据，不证明真实后端的双向权限、跨账号同步、持久化、频控或 WebSocket 推送。新能力默认关闭；legacy 旧发送端点无法提供超时重试幂等保证。后端完成契约后应使用两个独立账号逐项联调，再启用对应能力。

## 工作区布局与会话切换修订

- 主导航提供好友、私信两个直接入口。两页均移除可见页首介绍，保留屏幕阅读器标题；工作区填充可用高度，开发提示移至底部。
- `/messages` 和 `/messages/:userId` 使用同一可选参数路由及固定页面 key；始终保留过渡包装，从其他页面进入时使用全站过渡，内部切换复用同一个页面实例，避免包装变化导致重新挂载与闪烁。
- 切换会话仅更新右侧内容，保留列表搜索、筛选及每个会话的草稿。迟到的历史加载不改变另一会话的滚动位置。
- 浏览器验证首次切换、连续快速切换、会话列表往返、搜索及草稿保留；未触发整页淡入淡出，桌面和手机输入框完整可见。
